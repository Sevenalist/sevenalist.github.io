    什么是 Agent Skills？从 Prompt、Agent 到 MCP 的一次能力升级¶

    pilot 等 AI 工具，正在从“能够回答问题的聊天机器人”逐渐变成“能够完成任务的智能体”。

    与此同时，一个新的概念开始频繁出现：

    Agent Skills，智能体技能。

    在 GitHub 上，我们也能看到越来越多类似的项目：

    Text Only
    pdf-processing
frontend-design
code-review
data-analysis
spreadsheet
presentation

    这些名字看起来很像游戏里的“技能树”：安装一个 PDF Skill，AI 就学会了处理 PDF；安装一个表格 Skill，AI 就学会了制作 Excel。

    但这种理解并不完全准确。

    Agent Skills 并不会直接修改模型，也不会像重新训练模型一样，把某种知识永久写进 AI 的“大脑”。

    更准确地说：

    Agent Skill 是一套可以被 AI 智能体按需发现、加载和执行的专业工作手册。

    它通常以文件夹的形式存在，其中可以包含工作说明、参考资料、模板以及可执行脚本。它的作用，是告诉一个通用智能体：

    • 什么情况下应该使用这项技能；
    • 完成任务时应该遵循什么流程；
    • 应该调用哪些工具；
    • 哪些错误需要特别检查；
    • 输出结果必须符合什么标准。

    要真正理解 Agent Skills，还需要先弄清楚它为什么会出现。

    一、Agent Skills 并不是凭空诞生的¶

    Agent Skills 的出现，是 AI 使用方式不断演变的结果。

    大致来说，这个过程可以分为四个阶段：

    1. 直接向模型提问；
    2. 使用 Prompt 约束模型；
    3. 让 Agent 调用工具执行任务；
    4. 使用 Skill 为 Agent 提供专业工作流程。

    它们并不是简单的替代关系，而是一层一层叠加起来的。

    二、第一阶段：我们主要依靠 Prompt 指挥 AI¶

    早期使用大语言模型时，人们主要通过 Prompt，也就是提示词，来告诉模型自己想要什么。

    例如：

    请帮我分析这份销售数据，找出销售额下降的原因，并按照“结论、证据、建议”的结构输出。

    这条 Prompt 同时告诉了模型三件事：

    • 要做什么：分析销售数据；
    • 要关注什么：销售额下降的原因；
    • 怎样输出：结论、证据和建议。

    如果提示词写得更加详细，模型通常也会表现得更加稳定。

    于是，人们开始研究提示词工程，例如：

    • 怎样描述角色；
    • 怎样拆解任务；
    • 怎样给出示例；
    • 怎样规定输出格式；
    • 怎样要求模型进行检查；
    • 怎样减少模型产生幻觉。

    后来，很多产品又加入了系统提示词、自定义指令、项目说明和 Prompt 模板。用户可以把经常使用的要求提前保存下来，不必在每次对话中重复输入。

    但是，单纯依赖 Prompt 存在几个明显问题。

    1. Prompt 很容易变得越来越长¶

    假设一家公司希望 AI 按照内部规范制作报告，就可能需要在提示词里写明：

    • 使用什么字体；
    • 标题应该怎样编号；
    • 哪些数据必须核验；
    • 图表应该采用什么格式；
    • 哪些术语不能使用；
    • 报告需要经过哪些检查；
    • 输出文件应该如何命名。

    如果所有要求都直接塞进 Prompt，提示词很快就会变成一份几千字甚至几万字的说明书。

    2. 很多要求并不是每次都需要¶

    例如，一份完整的文档处理规范中，可能同时包含：

    • Word 排版规范；
    • Excel 公式规范；
    • PowerPoint 设计规范；
    • PDF 表单填写规范。

    但用户这一次只想制作一张表格。

    如果系统把所有规范都提前交给模型，不仅浪费上下文空间，还可能让模型受到无关信息干扰。

    3. Prompt 主要告诉模型“怎么回答”¶

    传统 Prompt 最擅长控制的是语言输出。

    但是，当任务从“回答一个问题”变成下面这些事情时，仅靠提示词就不够了：

    • 读取电脑上的文件；
    • 修改一份 Excel 表格；
    • 运行测试；
    • 操作 Git 仓库；
    • 查询数据库；
    • 填写 PDF 表单；
    • 上传生成的文件；
    • 根据执行结果反复修改。

    模型需要的不再只是一段说明，而是能够真正采取行动的环境。

    于是，Agent 开始出现。

    三、第二阶段：从聊天模型走向 Agent¶

    “Agent”通常被翻译为“智能体”或“代理”。

    在不同研究和产品中，Agent 的定义并不完全相同。但在实际应用中，可以把它理解为：

    一个能够围绕目标进行判断、调用工具、观察结果并继续行动的 AI 系统。

    普通聊天模型的工作过程大致是：

    Text Only
    用户提问
   ↓
模型生成回答
   ↓
任务结束

    而 Agent 的工作过程更像一个循环：

    Text Only
    接收目标
   ↓
分析当前情况
   ↓
选择下一步行动
   ↓
调用工具
   ↓
观察工具返回的结果
   ↓
判断任务是否完成
   ↓
没有完成则继续行动

    Anthropic 在介绍智能体时，将其概括为“大语言模型根据环境反馈，在循环中使用工具”。这种循环结构使模型不再只是生成文字，而是能够根据执行结果不断调整下一步行动。编程 Agent 说：

    修复这个项目中登录页面偶尔白屏的问题。

    Agent 可能会自行完成以下步骤：

    1. 搜索与登录页面有关的代码；
    2. 阅读错误日志；
    3. 找出可能的异步加载问题；
    4. 修改代码；
    5. 运行测试；
    6. 查看测试结果；
    7. 如果测试失败，继续修改；
    8. 最后生成修改说明。

    这里真正执行任务的是 Agent，而不只是底层的大语言模型。

    可以把它们简单地区分为：

    • 模型负责理解、推理和生成；
    • Agent负责组织模型、工具和执行循环。

    不过，Agent 很快又遇到了两个新的问题。

    四、Agent 遇到的第一个问题：工具连接过于混乱¶

    一个 Agent 如果想完成现实中的工作，就需要访问外部系统。

    例如：

    • 读取本地文件；
    • 查询 GitHub 仓库；
    • 查看 Google Drive；
    • 访问公司数据库；
    • 读取 Slack 消息；
    • 操作浏览器；
    • 查询日历；
    • 调用内部业务系统。

    在 MCP 出现之前，每个 AI 产品通常都要为每一个外部系统单独编写连接方式。

    例如，同样是连接 GitHub：

    • Claude 可能需要一套 GitHub 集成；
    • ChatGPT 可能需要另一套；
    • 某个 IDE Agent 又需要重新实现一套；
    • 企业自己的 AI 系统还需要再开发一遍。

    这就像每一台电脑都使用不同形状的接口，每连接一个新设备，都要重新制作一根专用数据线。

    为了解决这个问题，Anthropic 在 2024 年 11 月 25 日开源了 Model Context Protocol，也就是 MCP。它的目标是提供一种统一标准，让 AI 应用能够连接外部数据源和工具。五、MCP 是什么？

    MCP 的全称是：

    Model Context Protocol，模型上下文协议。

    官方经常把 MCP 比作 AI 世界中的 USB-C 接口。

    USB-C 本身不是鼠标、键盘或者硬盘，它只规定设备应该怎样连接和通信。

    同样：

    MCP 本身不是某个具体工具，而是一套让 AI 应用连接工具、数据和外部系统的通信标准。

    通过 MCP，服务器可以向 AI 应用提供几类能力：

    • Tools：可以执行的操作；
    • Resources：可以读取的数据和资料；
    • Prompts：可以调用的预设提示模板。

    例如，一个 GitHub MCP Server 可以向 Agent 提供：

    • 读取仓库文件；
    • 搜索代码；
    • 查看 Issue；
    • 创建分支；
    • 提交修改；
    • 创建 Pull Request。

    一个数据库 MCP Server 则可以提供：

    • 查看数据表结构；
    • 执行查询；
    • 获取查询结果；
    • 调用预先定义的业务接口。

    因此，MCP 解决的是：

    Agent 如何以统一方式连接外部世界。

    官方文档将 MCP 定义为连接 AI 应用与外部系统的开放标准，并明确指出，MCP 可以连接本地文件、数据库、搜索工具和各种业务工作流。以后，新的问题又出现了。

    六、Agent 遇到的第二个问题：它有工具，却不一定会正确工作¶

    假设我们给一个刚入职的员工提供了：

    • 一台电脑；
    • 公司数据库权限；
    • Excel；
    • PowerPoint；
    • PDF 编辑器；
    • 公司共享文件夹。

    这个员工现在已经拥有了完成工作的工具。

    但是，他仍然不一定知道：

    • 应该先查哪张表；
    • 哪些数据必须交叉核对；
    • 公司报告使用什么模板；
    • 图表中哪些颜色不能使用；
    • 哪些内容属于内部信息；
    • 提交报告前需要进行什么检查；
    • 什么情况下必须请示负责人。

    Agent 也面临同样的问题。

    MCP 可以让 Agent 访问数据库，但不会自动告诉它应该查询哪张表。

    工具可以让 Agent 修改 Excel，但不会自动告诉它公司要求怎样设置公式。

    浏览器可以让 Agent 打开网页，但不会自动告诉它完成某项业务时应该遵循什么顺序。

    这说明，真实工作不仅需要知识和工具，还需要另一种东西：

    程序性知识。

    所谓程序性知识，就是“怎样把一件事情做好”的经验，例如：

    • 工作步骤；
    • 判断标准；
    • 行业惯例；
    • 项目规范；
    • 常见错误；
    • 检查方法；
    • 特殊情况下的处理方式。

    过去，这些内容通常被写进很长的系统提示词、项目说明或者内部文档中。

    但随着 Agent 能够完成的任务越来越多，把所有说明都塞进系统提示词已经不可行。

    于是，Agent Skills 应运而生。

    七、Agent Skills 的正式诞生¶

    需要说明的是，“技能”“工具包”“工作流”等概念，在 Agent Skills 这个名称出现以前就已经存在。

    人们早已在使用：

    • 可复用 Prompt；
    • 自定义指令；
    • 工作流模板；
    • 插件；
    • 函数调用；
    • 项目说明文件；
    • 自动化脚本。

    因此，Agent Skills 并不是突然发明了“给 AI 写说明书”这件事。

    它真正的新意，是把这些内容整理成一种：

    • 基于文件夹；
    • 可以自动发现；
    • 可以按需加载；
    • 可以携带脚本和资料；
    • 可以组合使用；
    • 可以跨不同 Agent 移植

    的标准化技能包。

    2025 年 10 月 16 日，Anthropic 正式发布 Agent Skills。

    Anthropic 将其定义为由指令、脚本和资源组成的文件夹，Agent 可以发现这些文件夹，并在遇到相关任务时动态加载。月 18 日**，Agent Skills 被进一步发布为开放标准，使同一份 Skill 可以在不同兼容产品之间移植，而不再局限于单一 AI 产品。b Copilot、OpenAI Codex 等产品也陆续支持这一格式。GitHub 将 Agent Skills 描述为一种开放标准；OpenAI 的官方文档也说明，Codex 和 ChatGPT 的 Skills 建立在开放的 Agent Skills 标准之上。Agent Skills 的发展列一条简化时间线，可以写成：

    时间 发展
    早期 用户主要通过 Prompt 和系统指令约束模型
    2024 年 能够读写文件、运行命令的 Agent 快速发展
    2024 年 11 月 MCP 发布，开始标准化 AI 与外部工具之间的连接
    2025 年 10 月 Anthropic 正式发布 Agent Skills
    2025 年 12 月 Agent Skills 成为开放标准
    此后 GitHub Copilot、Codex 等智能体陆续支持这一格式

    八、Agent Skills 诞生之初，用在哪里？¶

    Agent Skills 最初最有代表性、也是最早被官方重点展示的应用场景之一，是：

    办公文档的读取、生成和修改。

    Anthropic 在介绍 Agent Skills 时，重点展示了 Word、Excel、PowerPoint 和 PDF 等文档处理能力。

    其中一个典型例子是 PDF Skill。

    大语言模型本来就知道 PDF 是什么，也能够理解从 PDF 中提取出来的文字，但这并不意味着它天然会：

    • 准确读取复杂 PDF；
    • 识别表单字段；
    • 修改 PDF 页面；
    • 填写可交互表单；
    • 合并多个 PDF；
    • 保留原有版式；
    • 生成可以正常打开的文件。

    为了可靠地处理 PDF，Agent 还需要知道：

    • 使用什么程序库；
    • 遇到扫描件怎么办；
    • 表单字段怎样识别；
    • 哪些情况下需要渲染页面检查；
    • 修改后怎样验证文件没有损坏；
    • 输出文件应该保存在哪里。

    Anthropic 官方在解释 Agent Skills 架构时，使用的正是 PDF Skill，并说明该 Skill 用来支持 Claude 的文档编辑能力。首批官方 Skill 也主要覆盖 PowerPoint、Excel、Word 和 PDF。期 Agent Skills，原因在于：

    1. 工作流程相对明确；
    2. 可以通过程序检查结果；
    3. 经常需要使用固定模板；
    4. 需要调用文件系统和代码执行工具；
    5. 仅靠自然语言生成很难保证文件正确；
    6. 大量操作可以重复使用。

    因此，下面可以用一个常见任务来理解 Skill 的作用：

    用户提供一份 Excel 销售数据，要求 AI 按照公司模板制作一份 PowerPoint 汇报。

    Agent 可能需要完成：

    1. 读取 Excel；
    2. 检查缺失值；
    3. 计算增长率；
    4. 生成图表；
    5. 套用公司 PowerPoint 模板；
    6. 编写结论；
    7. 检查文字是否超出页面；
    8. 导出并重新打开文件进行验证。

    这显然已经不是一条简单 Prompt 可以稳定完成的事情。

    九、一个 Agent Skill 里面有什么？¶

    一个最基础的 Skill，通常是一个文件夹。

    例如：

    Text Only
    sales-presentation/
├── SKILL.md
├── references/
│   ├── company-style-guide.md
│   └── chart-rules.md
├── scripts/
│   ├── validate_excel.py
│   └── check_slides.py
└── assets/
    └── company-template.pptx

    其中最重要的文件是：

    Text Only
    SKILL.md

    它通常由两个部分组成：

    1. 元数据；
    2. 工作指令。

    一个简化后的 SKILL.md 可能是：

    Markdown
    ---
name: sales-presentation
description: 根据销售数据制作公司标准汇报。用户要求分析销售数据、制作季度汇报或生成销售演示文稿时使用。
---

# 工作流程

1. 检查输入文件是否包含日期、地区、产品和销售额字段。
2. 不得直接删除缺失数据，先在报告中标记。
3. 同比增长率至少保留一位小数。
4. 使用 assets/company-template.pptx 作为模板。
5. 图表规则参见 references/chart-rules.md。
6. 生成后运行 scripts/check_slides.py。
7. 如果检查失败，修复后重新运行。

    这个文件并没有重新训练模型。

    它只是把一名有经验的员工可能掌握的工作方法，整理成 Agent 可以读取的形式。

    除 SKILL.md 外，Skill 还可以携带：

    1. 参考资料¶

    例如：

    • 公司术语表；
    • 代码规范；
    • API 文档；
    • 品牌设计规范；
    • 数据库结构说明；
    • 常见问题处理方法。

    2. 模板¶

    例如：

    • PowerPoint 模板；
    • Word 报告模板；
    • Excel 表格模板；
    • 合同模板；
    • 项目目录模板。

    3. 脚本¶

    例如：

    • 检查文件格式；
    • 统计数据；
    • 生成图表；
    • 转换文件；
    • 运行自动测试；
    • 验证输出是否合格。

    Agent Skills 的开放规范规定，一个 Skill 至少包含 SKILL.md，还可以包含 scripts、references、assets 等目录。十、Skill 为什么不会把上下文撑爆？

    Agent Skills 的核心设计之一，叫作：

    Progressive Disclosure，渐进式披露。

    意思是，Agent 不会在一开始就读取所有 Skill 的全部内容，而是按照任务需要逐层加载。

    整个过程通常分为三个层级。

    第一层：只读取名称和描述¶

    Agent 启动时，可能只会看到：

    Text Only
    name: sales-presentation
description: 根据销售数据制作标准汇报。

    这点信息很短，只用于让 Agent 判断：

    当前任务是否可能需要这个 Skill？

    第二层：加载完整的 SKILL.md¶

    当用户要求制作销售汇报时，Agent 判断该 Skill 与任务相关，于是读取完整工作流程。

    第三层：按需读取资料和运行脚本¶

    如果任务需要制作图表，Agent才读取：

    Text Only
    references/chart-rules.md

    如果任务已经生成完成，Agent 再运行：

    Text Only
    scripts/check_slides.py

    如果用户只要求查看数据，并不要求制作幻灯片，那么公司模板和幻灯片检查脚本可能始终不会被加载。

    这类似于一本工作手册：

    • 目录一直可见；
    • 相关章节按需翻开；
    • 附录只在必要时查阅；
    • 工具只在需要时使用。

    Anthropic 将渐进式披露视为 Agent Skills 的核心设计原则：Agent 平时只保留少量发现信息，任务匹配后才读取完整指令，其他参考文件则继续按需加载。十一、Prompt、Agent、MCP 和 Skill 到底是什么关系？

    这四个概念经常同时出现，但它们并不处于同一个层级。

    最简单的关系是：

    Text Only
    用户通过 Prompt 提出目标
            ↓
Agent 判断并组织任务
            ↓
Agent 加载相关 Skill
            ↓
Skill 告诉 Agent 应该怎样做
            ↓
Agent 通过 MCP 或其他接口调用工具
            ↓
工具读取数据、修改文件或执行操作
            ↓
Agent 检查结果并继续行动

    可以把它们比作一家公司的工作过程。

    概念 类比 核心作用
    Prompt 用户下达的任务 说明这一次要做什么
    Agent 执行任务的员工 判断、规划、行动和检查
    Skill 岗位操作手册 说明这类任务应该怎样做
    MCP 通用连接接口 让员工连接外部系统和设备
    Tool 具体设备或操作 真正读取、计算、修改或提交

    十二、Prompt 和 Skill 有什么区别？¶

    Prompt 是用户或系统向模型提供的指令。

    例如：

    把这份销售数据做成一份十页以内的季度汇报。

    它主要描述当前任务。

    Skill 则是可复用的专业流程，例如：

    • 怎样验证销售数据；
    • 怎样计算增长率；
    • 怎样选择图表；
    • 怎样套用模板；
    • 怎样检查幻灯片；
    • 怎样处理异常数据。

    二者最重要的区别，不只是“一个短、一个长”。

    Prompt 通常面向当前对话¶

    它回答的是：

    这一次要做什么？

    Skill 面向一类可重复任务¶

    它回答的是：

    每次遇到这类任务，通常应该怎样完成？

    Skill 可以包含 Prompt，但不只是 Prompt¶

    SKILL.md 中的说明本质上仍然会以文本形式进入模型上下文，因此从底层来看，它也会影响模型的提示环境。

    但一个完整 Skill 还增加了：

    • 名称和描述；
    • 自动发现机制；
    • 按需加载机制；
    • 文件夹结构；
    • 参考资料；
    • 模板；
    • 可执行脚本；
    • 可移植和可版本管理的封装。

    因此可以说：

    Prompt 是一段指令，而 Skill 是围绕某类任务组织起来的一整套可复用资源。

    把 Skill 简单理解为“高级 Prompt”并非完全错误，但会忽略它的文件组织、动态加载和脚本执行能力。

    十三、Agent 和 Skill 有什么区别？¶

    Agent 是任务的执行主体，Skill 是 Agent 可以调用的能力模块。

    一个 Agent 可以拥有很多 Skills，例如：

    Text Only
    Agent
├── PDF 处理 Skill
├── Excel 分析 Skill
├── PowerPoint 制作 Skill
├── 代码审查 Skill
└── 数据库迁移 Skill

    同一个 Skill 也可以被不同 Agent 使用。

    例如，一份符合开放标准的 PDF Skill，理论上可以被多个兼容的 AI 产品加载。

    因此：

    Agent 是“谁在工作”，Skill 是“它掌握了哪套工作方法”。

    Skill 不能脱离 Agent 自己完成任务。

    一个放在硬盘上的 SKILL.md 文件不会自动执行。必须有支持 Skills 的 Agent：

    1. 找到它；
    2. 判断是否相关；
    3. 读取其中的说明；
    4. 调用相应工具；
    5. 执行工作流程。

    另一方面，Agent 没有 Skill 也可以工作，只是更依赖模型临场发挥。

    十四、MCP 和 Skill 有什么区别？¶

    MCP 与 Skill 最容易混淆，因为两者都在“扩展 Agent 能力”。

    但它们解决的是两个不同问题。

    MCP 解决“怎样连接”¶

    例如：

    • 怎样连接 GitHub；
    • 怎样连接数据库；
    • 怎样读取 Google Drive；
    • 怎样调用企业内部服务；
    • 怎样让不同 AI 产品复用同一个工具接口。

    Skill 解决“连接之后怎样工作”¶

    例如：

    • 从 GitHub 中先查看哪些文件；
    • 修改代码后必须运行哪些测试；
    • 数据库迁移需要遵守什么步骤；
    • 从 Google Drive 中读取资料后怎样整理；
    • 生成报告时必须采用什么格式。

    可以用一句话概括：

    MCP 提供能力入口，Skill 提供能力使用方法。

    例如，一个数据库 MCP Server 向 Agent 提供了查询数据库的能力。

    而一个“销售分析 Skill”会告诉 Agent：

    1. 查询哪几张表；
    2. 使用哪些字段；
    3. 怎样处理退款；
    4. 怎样计算季度增长率；
    5. 哪些结果需要人工确认；
    6. 最终怎样生成报告。

    Skill 可以调用 MCP 提供的工具，但 Skill 并不依赖 MCP 才能存在。

    它也可以：

    • 运行本地脚本；
    • 使用 Agent 自带的工具；
    • 读取本地文件；
    • 只提供分析流程；
    • 调用普通 API。

    同样，MCP Server 也不一定需要 Skill。

    一个天气 MCP Server 可以只提供“查询天气”工具，Agent 根据当前 Prompt 自行决定怎样使用。

    十五、为什么 MCP 中也有 Prompt？¶

    MCP Server 除了提供 Tools 和 Resources，还可以提供预设 Prompts。

    这可能让人更加困惑：

    既然 MCP 也能提供 Prompt，那它和 Skill 还有什么区别？

    MCP Prompt 通常是一种通过服务器提供的预设提示模板。

    例如，一个代码管理 MCP Server 可以提供：

    Text Only
    review-pull-request

    用户调用后，系统得到一段预先写好的代码审查提示。

    它仍然主要是一份提示模板。

    而 Skill 更强调：

    • 自动发现；
    • 动态加载；
    • 完整工作流程；
    • 多份参考资料；
    • 文件模板；
    • 可执行脚本；
    • 针对一类任务的持续复用。

    因此：

    MCP Prompt 是 MCP 可以传递的一类内容；MCP 是通信协议；Skill 则是面向 Agent 的专业能力包。

    它们可以互相配合，但不能互相替代。

    十六、用一个完整例子理解四者关系¶

    假设用户提出：

    读取 Google Drive 中的第二季度销售表，制作一份符合公司模板的销售汇报，并把结论发到 Slack。

    第一步：Prompt 提出目标¶

    用户的这句话就是当前任务的 Prompt。

    它告诉 Agent：

    • 数据在哪里；
    • 要生成什么；
    • 结果发送到哪里。

    第二步：Agent 规划任务¶

    Agent 将任务拆成：

    1. 读取销售表；
    2. 检查数据；
    3. 分析销售趋势；
    4. 生成 PowerPoint；
    5. 检查文件；
    6. 提炼结论；
    7. 发送到 Slack。

    第三步：Agent 加载 Skills¶

    Agent 可能加载：

    • spreadsheet-analysis Skill；
    • sales-report Skill；
    • presentation Skill。

    这些 Skills 告诉 Agent：

    • 缺失数据怎样处理；
    • 销售额怎样计算；
    • 公司使用什么模板；
    • 每页允许放多少内容；
    • 图表如何配色；
    • 输出前如何检查。

    第四步：Agent 通过 MCP 连接服务¶

    Agent 使用：

    • Google Drive MCP Server 读取文件；
    • Slack MCP Server 发送消息。

    MCP 负责标准化连接方式。

    第五步：工具实际执行操作¶

    具体工具负责：

    • 下载 Excel；
    • 读取单元格；
    • 运行计算；
    • 创建 PowerPoint；
    • 上传文件；
    • 发送 Slack 消息。

    第六步：Agent 检查结果¶

    Agent 根据 Skill 中的要求运行检查脚本。

    如果发现：

    • 某页文字溢出；
    • 增长率计算错误；
    • 图表缺少单位；
    • 模板使用不正确；

    Agent 就继续修改，直到满足要求。

    在整个过程中：

    • Prompt 提出目标；
    • Agent 组织行动；
    • Skill提供方法；
    • MCP 提供连接；
    • Tool 完成操作。

    十七、Skill 和模型训练有什么区别？¶

    Skill 不等于训练，也不等于微调。

    模型训练或微调，通常会修改模型参数。

    训练完成后，模型的行为和知识会以某种方式写入模型权重。

    而 Skill 通常只是外部文件。

    当 Skill 没有被加载时，它不会影响模型。

    当 Skill 被删除后，模型也不会永久记住里面的内容。

    因此：

    方法 是否修改模型参数 是否按需加载 是否容易修改
    Prompt 否 当前对话加载 很容易
    Skill 否 是 容易
    微调 是 否 成本较高
    重新训练 是 否 成本很高

    Skill 的优势在于：

    • 制作成本较低；
    • 可以快速修改；
    • 可以放入版本控制；
    • 可以针对不同项目切换；
    • 不需要重新训练模型；
    • 可以在不同兼容 Agent 之间共享。

    但它也无法完全替代训练。

    如果模型本身无法理解某个复杂问题，仅靠 Skill 并不能凭空创造足够的推理能力。

    十八、Skill 会让 Agent 变成真正的专家吗？¶

    不一定。

    Skill 可以给 Agent 提供专业流程，但最终执行者仍然是大语言模型。

    它仍然可能：

    • 错误理解说明；
    • 选择了不合适的 Skill；
    • 漏掉某个步骤；
    • 错误调用工具；
    • 对结果作出错误判断；
    • 生成看似正确但实际错误的文件。

    Skill 更像一张地图或者一本操作手册。

    一张好地图可以让人少走弯路，却不能保证驾驶者绝不出错。

    而且，一份低质量 Skill 还可能让 Agent 表现得更差，例如：

    • 指令过于宽泛；
    • 工作流程本身存在错误；
    • 不同规则互相矛盾；
    • 引用了已经过期的资料；
    • 强制 Agent 执行不必要的步骤；
    • 把大量无关内容塞进上下文；
    • 在脚本中执行不安全操作。

    Agent Skills 官方的编写建议也强调，真正有效的 Skill 应该来自实际工作经验，而不是让模型凭空生成一些“遵循最佳实践”“妥善处理错误”之类的空泛要求。十九、安装 Skill 时需要注意什么？

    Skill 不一定只是静态文字，它还可能携带可执行脚本。

    因此，安装来历不明的 Skill，类似于安装一个来历不明的软件包。

    需要特别检查：

    • SKILL.md 要求 Agent 做什么；
    • scripts 目录里有什么程序；
    • 是否会读取隐私文件；
    • 是否会访问网络；
    • 是否会修改或删除数据；
    • 是否要求调用高权限工具；
    • 是否会上传本地信息；
    • 是否引用不可信的外部内容。

    Skill 和 MCP 的安全风险也不相同。

    Skill 的主要风险¶

    • 恶意工作指令；
    • 隐藏的脚本；
    • 错误的专业流程；
    • Prompt 注入；
    • 过期或有偏见的资料。

    MCP 的主要风险¶

    • 外部服务权限过大；
    • 身份认证配置错误；
    • 工具暴露敏感数据；
    • Agent 执行了高风险操作；
    • 不可信 MCP Server 返回恶意内容。

    一个 Skill 可能告诉 Agent“该怎样做”，一个 MCP Server 则可能真的赋予 Agent“做这件事的权限”。

    因此，二者都需要进行权限控制和来源审查。

    二十、怎样判断一个 Skill 是否值得使用？¶

    可以从几个方面判断。

    1. 任务范围是否明确¶

    好的描述通常会说：

    根据销售数据生成符合公司规范的季度汇报。

    而不是：

    帮助 Agent 完成所有商业工作。

    Skill 范围过宽时，Agent 很难判断什么时候应该加载，也容易受到大量无关规则影响。

    2. 是否包含真正有价值的专业经验¶

    好的 Skill 会告诉 Agent：

    • 应该使用哪张数据表；
    • 某个字段有什么特殊含义；
    • 哪种错误最常见；
    • 什么情况下必须停止；
    • 怎样验证结果。

    低质量 Skill 往往只会写：

    • 保持专业；
    • 深入分析；
    • 遵循最佳实践；
    • 注意准确性；
    • 妥善处理异常。

    这些要求听起来正确，却没有提供模型原本不知道的信息。

    3. 是否有可验证的完成标准¶

    例如：

    • 所有公式必须经过重新计算；
    • 所有页面不得出现文字溢出；
    • 代码必须通过测试；
    • 输出文件必须能够重新打开；
    • 报告中的数字必须可以追溯到原始数据。

    只有“生成一份高质量报告”，很难真正检查。

    4. 是否允许 Agent 根据情况调整¶

    Skill 应该提供可靠流程，但不应该把所有任务都机械地套进同一个模板。

    优秀 Skill 通常会明确：

    • 哪些步骤必须执行；
    • 哪些步骤可以选择；
    • 遇到异常时怎样处理；
    • 什么时候需要向用户确认；
    • 什么时候应当停止自动操作。

    5. 是否经过真实任务测试¶

    一份 Skill 能够正常被加载，不等于它真的有效。

    更可靠的方法是比较：

    • 不使用 Skill 时的结果；
    • 使用 Skill 后的结果；
    • 是否减少错误；
    • 是否增加不必要步骤；
    • 是否显著消耗更多时间和上下文。

    Skill 本身也需要像软件一样经过测试、迭代和版本管理。

    二十一、Agent Skills 真正改变了什么？¶

    Agent Skills 并没有发明提示词，也没有让模型突然获得新的智慧。

    它真正改变的是：

    人类经验向 AI Agent 传递的方式。

    过去，我们通常把经验散落在：

    • 对话记录；
    • Prompt 文档；
    • 员工手册；
    • 项目 Wiki；
    • 脚本；
    • 代码注释；
    • 模板文件；
    • 某个熟练员工的脑海中。

    Agent Skills 尝试把这些内容整理成一个统一的能力单元：

    Text Only
    一项技能
=
触发条件
+
工作流程
+
专业知识
+
参考资料
+
文件模板
+
可执行脚本
+
检查标准

    它让一个通用 Agent 可以根据任务，临时加载某一套专业工作方法。

    这也意味着，未来决定 Agent 工作质量的，可能不只是“它使用了什么模型”，还包括：

    • 它拥有哪些工具；
    • 它连接了哪些 MCP Server；
    • 它安装了哪些 Skills；
    • 这些 Skills 是否来自真正的专业经验；
    • 它是否能够正确选择并组合这些能力。

    结语：Skill 是写给 Agent 的工作手册¶

    现在可以用几句话概括这些概念：

    Prompt 告诉 AI，这一次要做什么。

    Agent 是能够围绕目标持续判断和行动的执行者。

    MCP 让 Agent 能够以统一方式连接数据、工具和外部系统。

    Skill 告诉 Agent，面对某一类任务时，应该怎样专业、稳定地完成。

    如果把 Agent 看作一名数字员工，那么：

    • 模型是它的大脑；
    • Prompt 是用户下达的任务；
    • Agent 系统是它的工作机制；
    • MCP 是连接公司系统的通用接口；
    • Tools 是它可以使用的具体设备；
    • Skills 是公司为它准备的岗位手册和标准作业流程。

    因此，对 Agent Skills 最通俗的解释仍然是：

    Agent Skill，就是一份能够被 AI 智能体自动发现、按需加载并重复使用的专业工作手册。
